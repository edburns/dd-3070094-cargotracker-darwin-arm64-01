The binding resolutions are:

- Expose deadline editing only in `src/main/webapp/admin/tables/listNotRouted.xhtml`; do not add it to routed, misrouted, claimed, or other tables.
- Preserve itinerary and allow aggregate recalculation; the application/facade operations remain generally callable by tracking ID even though this UI is scoped to Not Routed cargo.
- Use the established PrimeFaces dynamic-dialog lifecycle. The caller listens for `dialogReturn`, invokes the dialog launcher's return handler, and updates `tableNotRouted`.
- Require a non-null date, with no new chronological policy.
- Mandatory executable evidence is the JDK 17/Open Liberty build/start, direct HTTP checks, and complete `DEF789` browser flow. Preserve the historical Arquillian path without trying to modernize it.

Research on the prepared baseline established that metadata placement in the dialog must remain directly under the root element and that transient JMS activation-order warnings are acceptable only when all endpoints subsequently activate. Recurring batch authorization failures, deployment errors, or new feature-attributable FFDC files are not acceptable.

## Implement

Modify only:

- `src/main/webapp/admin/tables/listNotRouted.xhtml`

Within the existing Deadline column, replace the plain deadline presentation with a `p:commandLink` that:

- calls `changeArrivalDeadlineDateDialog.showDialog(cargoNotRouted.trackingId)`;
- continues displaying `cargoNotRouted.arrivalDeadlineDate`;
- uses the existing Font Awesome edit-icon style;
- has a stable component ID such as `arrivalDeadlineToUpdate`;
- listens for `dialogReturn`;
- invokes `changeArrivalDeadlineDateDialog.handleReturn`;
- updates `tableNotRouted`;
- has tooltip text exactly `Click to change cargo arrival deadline date.`

Follow the adjacent Destination column's established command-link structure and styling. Do not alter tracking-ID routing or destination editing.

Perform the complete `DEF789` acceptance flow:

1. Run `./mvnw clean package -Popenliberty liberty:run` on JDK 17.
2. Confirm the home page returns HTTP 200.
3. Open Administration, locate `DEF789`, and record its original deadline.
4. Confirm the deadline has the edit icon and exact tooltip.
5. Open the deadline dialog and verify origin/destination identify the same cargo.
6. Select a visibly different date and press Update.
7. Confirm the dialog closes, `tableNotRouted` refreshes, and the selected date is displayed.
8. Reload and confirm the value persisted.
9. Reopen and confirm the editor initializes to the changed date.
10. Cancel and confirm no further change.
11. Verify Destination editing still opens.
12. Verify selecting `DEF789` for routing still loads without an error page.

As additional regression gates, verify no deadline-edit affordance appears in the other Administration cargo tables, the command link preserves the original deadline text formatting, and the Ajax update targets an existing component without a component-not-found error.
